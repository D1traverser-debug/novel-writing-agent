# NOVEL_OS — Masterwork Distillation Protocol

version: 1.0
status: ACTIVE_SYSTEM_PROTOCOL
scope: lawful masterwork study -> craft evidence -> project benchmark -> bounded rule promotion
business_authority: D1traverser-debug/novel-writing-agent@main

## 0. Purpose

优秀作品不是“模仿库”，而是能力训练样本。本协议负责把名作/爆款/经典中的有效机制拆成可验证的小说技能，同时防止：

- 把成功作品的一切都误当成功因；
- 幸存者偏差；
- 只会总结“节奏好、人物立体、伏笔多”这类空话；
- 复制措辞、桥段、设定、人物关系或独特表达；
- 读过一本书就把能力自评为 L3/L4；
- 研究越积越多，却不回到生产。

该协议是 `protocols/NOVEL_MASTERY_MODEL.md` 的学习执行层；Masterwork evidence 默认只是 `LEARNING_EVIDENCE`，不能直接覆盖 `ACTIVE_RULEBOOK` 或项目 Canon。

## 1. Source / copyright boundary

允许的研究输入：
1. 官方/作者授权的免费阅读、试读、公开章节；
2. 用户合法提供或系统合法可访问的已购文本；
3. 作者访谈、创作谈、官方课程；
4. 合法书评、学术/媒体评论、读者反馈。

禁止把盗版全文、来路不明 TXT/EPUB、破解资源当训练源。仓库只保存：章节/位置引用、结构标签、极短必要引文、摘要与机制结论；不保存可替代原作阅读的大段正文。

## 2. Distillation unit

每部作品必须同时按三个尺度研究，禁止只做宏观剧情梗概。

### A. Macro — series / volume / arc
- reader contract / premise;
- mainline and terminal pressure;
- volume/unit turns;
- world-rule expansion;
- mystery/reveal ladder;
- character/relationship arcs;
- payoff debt / foreshadow horizon;
- escalation and rest rhythm;
- ending convergence.

### B. Meso — 3–10 chapter packet / sequence
- sequence objective;
- question opened / answered / replaced;
- irreversible state changes;
- engine diversity;
- relationship delta;
- emotional contour;
- information asymmetry;
- next-packet handoff.

### C. Micro — chapter / scene / paragraph function
必须主动扫描，而不是等用户提醒：
- first-screen acquisition;
- scene goal / friction / turn / consequence;
- plot causality and progression;
- psychological portrayal;
- emotional progression;
- environmental / spatial description;
- sensory selection;
- action / fight clarity;
- dialogue / subtext / voice;
- POV / psychic distance;
- exposition and world-rule delivery;
- mystery clue / red herring / reveal;
- character-specific behavior;
- relationship power/trust shift;
- transitions / compression / summary;
- humor and relief;
- motif / symbolic recurrence;
- sentence and paragraph rhythm;
- chapter-end reading reason;
- mobile readability / cognitive load.

如果用户指出一个这里没有覆盖的一级维度，视为 C20 meta-learning incident：先扩 competency lattice，再继续研究，而不是只临时加一个 reviewer 问题。

## 3. Required study pipeline — D0–D12

### D0 RIGHTS_AND_SOURCE
确认文本/章节来源合法，记录来源等级、可见范围、时间与缺口。

### D1 SELECTION_RATIONALE
说明为什么选这部作品、它能训练哪些 C01–C20 能力、哪些能力不该向它学习。

### D2 PHASE_MAP
按实际结构分阶段，而不是平均抽样。最低包含：
- opening/acquisition；
- first major payoff；
- early relationship/world expansion；
- mid-series escalation；
- late convergence；
- ending/payoff；
- 作者/读者明确指出的强段和弱段。

### D3 COLD_READ_TRACE
第一遍只记录读者体验：此刻想知道什么、担心什么、相信什么、误解什么、为何继续读。禁止先用理论替读者感受。

### D4 STRUCTURAL_ANNOTATION
画出 state change / causal chain / question-answer ladder / reveal ladder / relationship delta / world-rule delta。

### D5 MICROCRAFT_ANNOTATION
逐样本分析心理、环境、对白、动作、POV、信息释放、句段节奏等微观技术；必须回答“这个描写改变了什么”，不能只统计修辞。

### D6 POSITIVE_NEGATIVE_DIFF
同一作品同时记录：
- 有效机制；
- 无效/代价高/后期暴露风险的机制；
- 作者自我复盘；
- 高信号读者分歧。

成功作品不享有“全自动正确”。

### D7 ABLATION / COUNTERFACTUAL
至少做一个反事实：删掉/延后/改写某机制后，会损失什么？如果几乎不损失，它可能只是表面风格，不是核心机制。

### D8 CROSS-WORK_TRIANGULATION
重大通用规则不得只从一部作品晋升。至少找一个同类作品和一个异类高质量作品做交叉验证，区分“作者个人风格”与“可迁移机制”。

### D9 PROJECT_TRANSFER_EXPERIMENT
把机制迁移到当前项目的新材料，禁止复制原作表达/事件。记录候选 A/B、预期收益和副作用。

### D10 ADVERSARIAL_REVIEW
由相应 competency reviewer 挑刺：是否过拟合原作？是否与项目身份冲突？是否把复杂度当质量？是否增加认知负荷？

### D11 PROMOTION
研究结论按以下层级晋升：
`REFERENCE -> EXPERIMENTAL -> PROJECT_PROVEN -> ACTIVE_RULE -> CROSS_PROJECT_VERIFIED`

- REFERENCE：观察到；
- EXPERIMENTAL：有明确机制假说；
- PROJECT_PROVEN：当前项目 benchmark/候选正文验证；
- ACTIVE_RULE：多次项目内验证且收益稳定，可进入 Rulebook；
- CROSS_PROJECT_VERIFIED：跨不同项目 + 外部结果验证，可支撑 L4。

### D12 STOP / DECAY
达到当前决策需要的证据就停止研究回生产。平台、类型或项目变化后，旧规则可降级；不把研究库存当永恒真理。

## 4. Microcraft benchmark definitions

### 4.1 Psychological portrayal
不是“写心理活动越多越好”。必须能控制以下通道：
- attention：角色此刻首先注意什么；
- interpretation：同一事实被角色怎样解释；
- desire/fear collision；
- bodily leakage / involuntary reaction；
- suppression / avoidance；
- memory trigger only when causally relevant；
- decision and aftershock；
- subtext between thought / speech / action。

Benchmark：删去显式情绪标签后，读者仍能从注意、动作、选择和语言判断主要情绪；同时不能把角色写成全知分析器。

### 4.2 Environment / atmosphere
环境描写至少承担一项功能，优先多功能：
`ORIENTATION / CONSTRAINT / CLUE / THREAT / CHARACTER_LENS / EMOTION / WORLD / FORESHADOW / ACTION_SURFACE`。

Benchmark：若删除一段环境描写，场景方向、情绪、选择、信息或世界均不受影响，则其 page-cost 需要重新证明。

### 4.3 Plot progression
每个保留场景至少改变一项：
`GOAL / KNOWLEDGE / RELATIONSHIP / RISK / RESOURCE / LOCATION / WORLD_MODEL / MORAL_COMMITMENT`。

章节/sequence 必须能画出因果箭头，而不是“发生了很多事”。答案最好改变或升级问题，而非只增加新名词。

### 4.4 Dialogue
检查：目的冲突、权力变化、隐藏意图、角色声纹、打断/回避/错答、行动穿插。Q&A 信息采访不能长期成为默认模式。

### 4.5 Emotion
情绪必须有 cause -> pressure -> behavior -> consequence -> aftershock。高强度事件后没有余震，是常见假情绪。

### 4.6 Quality audit
审核顺序固定从高到低：
`reader contract -> architecture -> character/relationship -> mystery/world -> sequence -> scene -> POV/emotion/dialogue/environment -> prose rhythm -> sentence/copyedit -> artifact/platform`。

禁止先润色一个结构失败的章节。

## 5. Masterwork-specific anti-overfit questions

每次必须回答：
1. 这是作品成功的必要机制，还是作者特色？
2. 同样机制在该书哪里失效或被读者批评？
3. 如果移植到当前项目，会不会伤害项目身份？
4. 该机制依赖作者已有读者基础/超长篇幅/特定题材吗？
5. 能否用更低复杂度实现同样读者效果？
6. 是否有现实平台数据或跨作品证据支持？

## 6. Current priority corpus policy

FQ001 当前优先研究顺序由能力缺口决定，不按名气排行：
- 规则悬疑 / 长线谜团 / 群像 / 高密度网文推进：`《十日终焉》`；
- 后续再根据缺口选择世界观、人物关系、心理、文风、场景等专项对照作品。

任何单一作品都不得成为 NOVEL_OS 的“唯一写作老师”。
