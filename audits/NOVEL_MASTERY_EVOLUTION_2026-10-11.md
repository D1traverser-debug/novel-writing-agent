# Novel Writing Agent — Mastery Evolution Audit

Date: 2026-10-11
Artifact class: LEARNING_EVIDENCE / SYSTEM_EVOLUTION_AUDIT
Execution authority: NO — promoted behavior lives in SKILL / protocols / project authority after validation.

## Trigger

User challenged a real omission: the previous evolution pass improved the owner’s learning/rebase machinery but did not fully evolve the owner’s own novel-craft capability model, audit coverage, worldbuilding discipline or long-form outline depth. The user explicitly delegated these decisions and should not have to name the missing craft dimensions one by one.

## M0 — Signal classification

This is not a request for “more rules” or “more agents.” It is a capability-gap incident:

- the owner had many useful craft rules;
- the owner had a 30-chapter beat outline;
- but there was no explicit complete competency ontology, no mastery depth/evidence standard, and no series-level outline binding ending/theme/world/character/mystery/retention together.

## M1 — Failure model

Observed failure modes:

1. **Checklist competence without mastery model** — the owner could audit scenes/chapters but could not prove it knew the full space of skills it should audit.
2. **Architecture under-specification** — `ARC_001.md` was a useful chapter-beat list, but not a full series architecture: no durable series→volume→arc→chapter hierarchy, global character arc, relationship arc, world-rule reveal ladder or terminal thematic constraint.
3. **Worldbuilding fragmented into project profile/rules** — world/system rules existed, but there was no explicit competence standard for consequences, limitations, social ripples, exploit surfaces and reveal staging.
4. **Learning depth undefined** — “read a course / add a rule” could be mistaken for “mastered.”
5. **User reminder dependency** — the user had to ask whether the agent had learned worldbuilding, outlining, audit rules and other craft disciplines. This is itself a meta-learning failure.

## M3 — Evidence scout

### Current Fanqie first-party evidence

Current Creator Academy curriculum explicitly treats the following as separate learnable craft areas: topic selection, pre-writing, outlines, story setting/world/character/timeline, openings, plot, hooks, immersion, character creation, revision, long-form updating/anti-blocking, acquisition and IP development.

Current high-end long-form guidance emphasizes:
- complex/saturated protagonists;
- distinctive or deepening worldbuilding;
- nested suspense where answers generate larger questions;
- rhythm with tension and relief rather than unbroken pressure;
- long-range foreshadow/payoff closure.

Current revision guidance explicitly distinguishes chapter-level defects from problems that require multi-chapter or outline-level reconstruction, and recommends comparing equivalent word-count windows against strong same-category works and real retention/follow-read data.

### General craft evidence

Accepted as diagnostic methods, not mandatory formulas:
- Sanderson: reader understanding controls how strongly a speculative system can solve conflict; limitations/costs matter more than power accumulation; expand existing rules before adding new ones.
- Writing Excuses: pre-writing can include outline/worldbuilding/ending; outline depth should stop before it becomes prose; worldbuilding implications ripple through plot/character; mysteries benefit from solution-first clue design, fair play and staged reinterpretation; dialogue subtext is created by the gap among text/context/meaning.
- Scene/Sequel: action and reaction must chain causal choice and consequence.
- Value-shift / crisis-choice analysis: a scene should change state, not merely contain activity.
- Character-arc/theme methods: external plot choices and internal belief/value change should constrain each other.

### Existing owner evidence

Strengths already present:
- scene / dialogue / suspense / fairness / domain reality / longform / theme / foreshadow / emotion / reader-memory / release rules;
- Canon ledgers for characters, drives, threads, foreshadow, timeline, reader promises;
- role-separated review and deterministic evidence guards;
- current front-arc rebase correctly challenged the old chapter-by-chapter patch plan.

But these strengths were fragmented across Rulebook, Project Profile and audit process. There was no single answer to “what does the agent need to master, and how do we know it mastered it?”

## M4 — Candidate solutions

### A. Add more reviewer agents
Rejected. More named roles do not create missing knowledge or prove mastery.

### B. Put every writing course into Writer context
Rejected. Causes context bloat, imitation risk and inconsistent production behavior.

### C. Add a giant universal formula book
Rejected. Overfits one platform/project and turns heuristics into dogma.

### D. Create one system-level competency/mastery model + one project master outline, while keeping current Rulebook and Canon separation
Accepted.

Why:
- unique non-duplicating role;
- solves “what to learn / source / depth / evidence” directly;
- lets production context remain compact;
- lets each project instantiate only relevant competencies;
- supports auditing the auditor.

## M6 — Mastery depth decision

Five-level mastery model adopted:
- L0 unmapped;
- L1 conceptual;
- L2 operational with scaffold;
- L3 project-ready;
- L4 transfer-verified.

Critical rule: reading/research alone never establishes L2/L3/L4.

For high-impact active project decisions, core capability target is L3. L4 requires repeated cross-project/outcome evidence and must not be claimed from this project alone.

## M7 — Audit evolution

Old audit architecture mainly asked “does the chapter pass?”

New audit architecture distinguishes:
- Gate A concept/series design;
- Gate B arc/packet architecture;
- Gate C chapter/scene production;
- Gate D revision diagnosis by defect level;
- Gate E release/platform.

A downstream gate cannot permanently hide an upstream defect. For example, excellent prose cannot pass a broken series architecture; chapter pacing fixes cannot repair a wrong mainline; detailed world logic cannot replace emotional attachment.

## M9 — Benchmark policy

Before a competency is considered L3 for a project, require an applied benchmark. Minimum library:
- architecture alternative/falsification;
- world implication/limitation/exploit test;
- character decisive-choice map;
- mystery solution-first clue ladder;
- scene state-change test;
- dialogue subtext test;
- cold-read prose/texture test;
- pacing equivalent-window comparison;
- revision seeded-defect diagnosis.

## M10 — Second-order challenge

Negative-space checks:
- Does a mastery matrix become bureaucracy? Mitigation: it stays out of Writer context; only relevant slices are pulled.
- Does “master outline” make discovery impossible? Mitigation: label LOCKED / PLANNED / FLEX / HYPOTHESIS; ending constraints are stronger than scene details.
- Can the owner claim mastery because this file exists? No. Mastery requires applied benchmark evidence and outcomes.
- Can platform heuristics become universal art laws? No. Platform evidence remains platform-specific.
- Can masterwork study become imitation? No. Extract functions/trajectory only; no phrasing/trope cloning.
- Can reviewer coverage still miss a capability? C20 requires explicit gap discovery after every major failure and periodic ontology review.
